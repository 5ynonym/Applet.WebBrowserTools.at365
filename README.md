# Applet.WebBrowserTools.at365

AppDock用のブラウザー便利コマンド集です。ブラウザー以外のアプリでも使えます。Windows x64 / AppDock 0.26.0以降が必要です。v0.3.1は.NET 10/WPFを含む単一EXEで、追加の.NETランタイムやブラウザ拡張のインストールは不要です。

## 導入・更新

1. AppDockをトレイの「終了」から完全終了します。
2. 配布物の `extension.json`、`Applet.WebBrowserTools.at365.exe` を、AppDock.at365.exeの隣の `extensions/Applet.WebBrowserTools.at365/` に配置します。更新時も配布物一式をそろえて置き換えてください。
3. AppDockを起動し、「Applet」一覧で有効にします。操作やキーの割り当てはAppDockから行います。

利用するPCにはAppDockの動作環境が必要です。詳細は[AppDockの導入案内](../AppDock.at365/README.md)を参照してください。

旧DLL版から更新する場合は、同じ配置先の `Applet.WebBrowserTools.at365.dll` と `Applet.WebBrowserTools.at365.deps.json` を取り除いてください。既存のコマンドIDと送信キー設定はそのまま使えます。

## コマンド

IDの共通接頭辞は `at365.web-browser-tools.` です。

| ID | 操作 | 操作メッセージ／既定の送信キー |
| --- | --- | --- |
| close-tab | タブを閉じる | Ctrl+F4 |
| back | 戻る | ブラウザーの「戻る」 |
| forward | 進む | ブラウザーの「進む」 |
| reload | リロード | ブラウザーの「再読み込み」 |
| super-reload | スーパーリロード | Ctrl+F5 |
| toggle-fullscreen | 全画面を切り替え | F11 |
| new-tab | 新しいタブを開く | Ctrl+T |
| new-window | 新しいウィンドウを開く | Ctrl+N |
| previous-tab | 前のタブへ | Ctrl+Shift+Tab |
| next-tab | 次のタブへ | Ctrl+Tab |
| restore-tab | 閉じたタブを復元 | Ctrl+Shift+T |

通常リロードとスーパーリロードを別々に実行できます。Watchの旧Reloadに相当する操作はスーパーリロード（Ctrl+F5）です。

## 使い方・設定

AppDockで有効にして、ショートカットやマウスジェスチャーへコマンドを割り当てます。実行する場所は各割り当ての条件で設定してください。コマンド自体はプロセス名やChromiumのウィンドウクラスで制限せず、今アクティブなウィンドウへ操作を送ります。AppDockが最前面なら、AppDockが送信先になります。

「Applet → WebBrowserTools.at365 → 設定」で、キー送信の8コマンドを個別に変更できます。保存後すぐ反映し、IDは変わりません。「送信キー」はアクティブなウィンドウに送るキーで、コマンドを呼び出すグローバルキーとは別です。同じキーをグローバル登録すると対象へ届かない場合があるため、異なる組み合わせにしてください。

記法は `Ctrl+W` / `Ctrl+Shift+T` / `Alt+Left` / `F11`。Ctrl、Alt、Shift、Winと、英数字、F1〜F24、Enter、Tab、Esc、Space、Backspace、Delete、Insert、Home、End、PageUp、PageDown、矢印キーに対応します。WinForms SendKeysの `%{F4}` のような記法は使用しません。

不正な設定変更は直前の有効なコマンド設定を保持します。ただし不正値がホストに保存された状態で再起動すると有効化に失敗するので、設定欄を修正してから再起動してください。

ブラウザー以外で使う場合は、そのアプリに一致する条件、または全体で使える条件へ割り当てを変更してください。本体の「ブラウザー」条件用のプロセス一覧とChromium制限は、その条件の判定に使われます。Applet側で追加の対象制限は行いません。初期ジェスチャーの「ブラウザー」条件と、利用者が保存した割り当ては更新で変更しません。

各アプリがWM_APPCOMMANDや送信キーを受け付けるか、何を実行するかはアプリ側の実装に依存します。コマンド名はブラウザーでの用途を表しています。

起動操作の修飾キーが離れるまで最大2秒待ち、待機中の最前面変更で中止します。ジェスチャーは開始したウィンドウが最前面のままの場合だけ送信します。アプリの起動・背面ウィンドウの探索・強制フォーカス移動は行いません。メッセージが未処理またはタイムアウトした場合は失敗を報告します。管理者権限のアプリへの操作はWindowsに制限されることがあります。

## マウスジェスチャー

v0.3.0から入力処理と割り当て設定をAppDock本体へ移しました。「設定 → マウスジェスチャー」で、このAppletの11コマンドに加えて他のAppletや本体コマンドも割り当てられます。「ブラウザー」条件用のexe一覧とChromium制限も同じ画面にあります。v0.3.1以降は、その条件以外で呼び出したコマンドにもApplet側のブラウザー制限をかけません。

従来の上下左右・ホイール上下・左/中クリックの8操作、距離、間隔、待機表示の位置・不透明度は引き継ぎます。新規導入時の既定値は、上＝タブ復元、下＝リロード、左＝戻る、右＝進む、左クリック＝タブを閉じる、中クリック＝新しいタブ、ホイール上＝前のタブ、下＝次のタブです。

右ボタンを押しながらのキー入力にも対応します。操作方法と除外・一時停止は[AppDockの案内](../AppDock.at365/README.md#マウスジェスチャー)を参照してください。ブラウザ操作コマンドIDと送信キー設定は変更しません。

Watchなど他のジェスチャーソフトと同時に使う場合は、フックの競合を避けるため一方だけを有効にしてください。

## AppDockからの更新

AppDock 0.22.0以降では「設定 → バージョン情報・更新」の一括更新、またはこのAppletの個別更新ボタンを利用できます。配布元が`update.json`と`update.zip`を提供している場合に対応します。更新元は「インストール済みのApplet」の「更新元の設定」で変更し、保存してください。ローカルフォルダー・UNC・HTTP(S)・GitHub Releaseに対応し、「既定に戻す」も利用できます。

更新内容を確認して再起動すると配布ファイル一式を交換します。AppDock側の設定・有効状態・保存データは保持します。詳細は[AppDockの更新操作](../AppDock.at365/README.md#アップデート)を参照してください。

開発・ビルドについては[開発ガイド](DEVELOPMENT.md)を参照してください。
